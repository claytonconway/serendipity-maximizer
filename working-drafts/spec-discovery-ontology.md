# Spec S1-0 · Serendipitous Discovery Ontology

**Author:** Fleming (Discovery Scientist) · **Date:** 2026-07-28
**Status:** rev 3 — S1-1-coupling edits applied (Flags A–E: `BridgeShape` rescoped, similarity≠serendipity split into soft+hard layers, priority FLOOR→soft floor, density→ValueScore-weighted, ValueScore/RankScore registered as derived measures). rev 2 was LIVE on public master (PR #1); this rev is a spec **edit** requiring a second framework PR (Orin shepherds).
**Sprint item:** S1-0 (upstream of all). **Artifact type:** spec / vocabulary. No framework code touched.
**Boundary:** checked against `.boundary-blocklist` — no blocked terms; sample cases reuse the repo's existing generic board data (warehouse robotics / cold-storage / SRE).

> **One-line charter.** A shared, typed vocabulary for characterizing a discovery, so that
> "valuable surprise" becomes a *region* in a defined space rather than a gut call — and so a
> *cluster of discoveries in one domain* becomes a **measurable** signal, not an anecdote.

---

## 0. What this is — and how it's grounded

This ontology characterizes **a discovery** along orthogonal **dimensions (facets)**, defines
**typed relationships** between discoveries, and ships **validators** that decide whether a
characterization is well-formed. It is the vocabulary that S1-1 (PO defines the valuable region),
S1-2 (distance band), and S1-3 (funnel + density → venture-candidate) all inherit.

It is **not**: the embedding engine (later, transient-built), the board schema rewrite (deferred),
or the acceptance definition itself (that's the PO's S1-1 call, made *using* this).

**Grounding principle: adopt a standard rather than invent one — but never force a standard where
none fits.** Most of this ontology is standard, tool-checkable machinery. A few parts are genuinely
novel epistemology with no standard; those are purpose-built and labelled as such. The fit judgment
is explicit per component (§0.1) and the places a standard *doesn't* fit are captured in §8, because
that reasoning is itself a durable output.

**Guardrail carried through every facet: similarity ≠ serendipity.** Nearest-neighbor returns the
obvious. Serendipity is the *mid-distance, cross-domain* neighbor. Per the S1-1 reframe this is now
enforced in **two complementary layers**, not one: (1) a **soft value weight** — the peaked `g_dist`
term in S1-1's ValueScore down-weights too-close (cliché) and too-far (noise) *without ever excluding*
the discovery; and (2) a **hard claim-integrity check** — `BridgeShape` (§7.2) rejects an edge *typed*
`bridges` whose endpoints aren't mid-distance, which **retypes the claim, not the discovery**. Value
judgment = soft; data-integrity = hard. (Reconciliation: `spec-value-weighting.md` §6.)

### 0.1 Standards fit map

| Component | Standard adopted | Fit judgment |
|-----------|------------------|--------------|
| Substrate — `Discovery` class, facet properties, typed edges | **OWL 2 / RDF** | **Strong.** Classes + datatype/object properties are exactly what OWL models. |
| F7 Provenance | **PROV-O** | **Strong.** A discovery is a `prov:Entity` generated by a capture `prov:Activity`, attributed to a `prov:Agent`. Provenance is PROV-O's whole purpose. |
| §3 Domain scheme (anchors F2) | **SKOS** | **Strong.** Domains are a controlled concept scheme with hierarchy — SKOS's core use case. |
| §7 Validators | **SHACL** | **Good, with two gaps.** Node + most edge constraints are core SHACL shapes. Acyclicity and cross-domain counting exceed core SHACL → SPARQL-based SHACL (`sh:sparql`). See §7.3 / §8. |
| Board JSON ↔ RDF bridge | **JSON-LD** | **Strong.** A JSON-LD `@context` maps the board's existing JSON fields to RDF terms — no board rewrite, just a context. |
| F1 Discovery Type (A/B/C/D) | *purpose-built* (shell publishable as SKOS) | The four types are novel project epistemology; the *vocabulary shell* could be a SKOS scheme for interop, but the content is ours. |
| F3 Domain-Distance bands | *purpose-built* (embedding-derived) | No standard defines a "mid-distance serendipity band." SKOS anchors domain *identity*; continuous distance is computed by embeddings, layered on top. |
| F4 Surprise Magnitude | *purpose-built* | A novel epistemic measure (assumption-violation). No standard. |
| F9 Serendipity Potential | *purpose-built* | Novel scoring factor. No standard. |
| §6 Density + venture-candidate flag | *purpose-built* | Novel engine output. No standard; built on PROV-O time + SKOS anchors. |

Net: **four W3C standards adopted** (OWL/RDF, PROV-O, SKOS, SHACL) + JSON-LD as the serialization
bridge; **five components purpose-built** because they are the genuinely new science this project
exists to do.

## 1. The node: a Discovery

A **Discovery** is the atomic node — modelled as an `owl:Class` (`:Discovery`, itself a
`prov:Entity`). Each is characterized by nine facets. Seven are stored or derivable from what the
board already persists (`app/discovery-board.jsx`); two are **named minimal additions**. The split is
explicit so S1-3 can be built off stored fields plus a small, named delta.

| # | Facet | RDF property (sketch) | Scale / range | Board field today | Status |
|---|-------|-----------------------|---------------|-------------------|--------|
| F1 | **Discovery Type** | `:discoveryType` (∈ A/B/C/D scheme) | categorical `A / B / C / D` (Anomaly / Bridge / Constraint-flip / Scale-shift) — *one* facet | `type` | ✅ stored |
| F2 | **Domain Anchor** | `:primaryDomain` / `:secondaryDomain` → `skos:Concept` | 1 primary + 0–n secondary, from the SKOS domain scheme (§3) | partial in `sourceAgent`+`tags[]` | ⚠️ **NEW** `domains[]` |
| F3 | **Domain-Distance** | `:domainDistance` / `:distanceBand` | continuous `0.0–1.0`; bands `too-close / serendipity-band / too-far` (§2.1) | — | ⚠️ **NEW** (embedding-computed; ontology fixes scale + bands) |
| F4 | **Surprise Magnitude** | `:surprise` | ordinal `1–5` (`1 expected` … `5 violates a held assumption`) | — (implicit in `summary`) | ⚠️ **NEW** `surprise` |
| F5 | **Impact** | `:impact` | `1–10` | Impact factor of `priorityScore` | ✅ stored (as a factor) |
| F6 | **Generality** | `:generality` | ordinal `point / vertical / platform / universal` | — (implicit) | ⚠️ **NEW** `generality` |
| F7 | **Provenance** | PROV-O (§5) | `prov:wasGeneratedBy` capture Activity `{ sourceAgent, discoveredBy, discoveredDate, captureMode }` | `sourceAgent`,`discoveredBy`,`discoveredDate` | ⚠️ partial — **NEW** `captureMode` |
| F8 | **Lifecycle State** | `:lifecycleState` | `New → Reviewing → Team Triage → Decision → Active → Banked` | `status` | ✅ stored |
| F9 | **Serendipity Potential** *(derived)* | `:serendipityPotential` | `1–10` | Serendipity_Potential factor of `priorityScore` | ✅ stored (as a factor) |

**Minimal board delta:** `domains[]`, `distanceBand` (or raw `domainDistance`), `surprise`,
`generality`, `captureMode`, and typed `relations[]` (§4). Everything else the board already holds.
Priority already decomposes as `(Impact × Serendipity_Potential) ÷ Effort_weight`
(`SKILL.md` §Step 3); F5 and F9 are the two numerator factors surfaced as first-class facets.

### 1.1 Why these facets (and no more)
- **F1 Type** = *what kind* of surprise. **F3/F4** = *how surprising* (geometry + felt magnitude —
  two signals on purpose: a big embedding jump isn't always a felt surprise, and vice-versa).
  **F5/F9** = *worth pursuing*. **F6** = *how far it generalizes*. **F2/F7** = *where it lives and how
  it arrived* — and together are the two facets that make **domain-density** measurable (§6).
- Facets are **orthogonal** by design: Type ≠ Impact; Surprise ≠ Distance; Generality ≠ Impact.
  Over-collapsing them is how "valuable surprise" degenerates back into one gut number.
- Scope discipline (risk: *ontology over-engineered / academic*): nine facets, four typed edges. If a
  facet doesn't feed S1-1/S1-2/S1-3, it isn't here. Adopting standards keeps it lean *and*
  tool-checkable rather than bespoke.

### 1.2 Derived measures (registered here, defined in S1-1)
Two computed measures ride on top of the facets; registered in the ontology as derived properties so
downstream specs share one definition:

| Measure | RDF property | Definition (canonical source) |
|---------|--------------|-------------------------------|
| **ValueScore** ∈ [0,1] | `:valueScore` | `TypeMult(F1)·[w_dist·g_dist(F3)+w_surp·g_surp(F4)+w_imp·g_imp(F5)+w_gen·g_gen(F6)+w_sp·g_sp(F9)]` — the graded, no-exclusion value weight. See `spec-value-weighting.md` §1 (weights PO-ratified). |
| **RankScore** | `:rankScore` | `ValueScore ÷ Effort_weight` — pursuit ordering; preserves the board's existing priority intuition. |

These are *derived* (not stored facets): recomputed from F1/F3/F4/F5/F6/F9 as weights tune. `ValueScore`
is what the density sum (§6) weights by, and what the soft floor (S1-1 §4) reads.

## 2. Facet detail: the two purpose-built axes that do the heavy lifting

### 2.1 F3 · Domain-Distance — where the guardrail is enforced (purpose-built)
Domain-distance is the semantic distance between the domains a single discovery *connects*
(intra-discovery). No W3C standard defines a "serendipity band," so this is purpose-built; S1-2
formalizes the thresholds empirically. S1-0 fixes the **scale and three qualitative bands**:

```
0.0 ─────────── too-close ──┊── serendipity-band ──┊── too-far ─────────── 1.0
   (cliché / restated       (mid-distance,           (noise / non-sequitur;
    similarity; "same        cross-domain; near        no transferable
    idea, same domain")      enough to be relevant,    mechanism)
                             far enough to be
                             non-obvious)
```

- Band **thresholds are `TBD-S1-2`** — S1-2 sets them with empirical basis. S1-0 owns only the
  *shape*: three bands, serendipity is the middle one.
- **Two-layer home of "similarity ≠ serendipity."** A discovery whose connected domains sit in
  `too-close` is a restatement; in `too-far` is likely noise. Handled in two ways: **softly** — the
  peaked `g_dist` value weight (S1-1) scores both tails low but **never excludes** the discovery; and
  **hard** — shape `BridgeShape` (§7.2) rejects a *bridge claim* outside the band (retype, don't drop).
  The band edges `[τ_lo, τ_hi]` both layers reference are set empirically in S1-2.
- **Relationship to SKOS (§3):** SKOS gives each domain a stable identity and a broader/narrower
  hierarchy; it does **not** give a continuous metric. Distance is embedding-derived and *anchored to*
  SKOS concepts. (Flagged in §8 — this is the cleanest example of a standard fitting the identity
  layer but not the metric layer.)

### 2.2 F4 · Surprise Magnitude — kept separate from distance on purpose (purpose-built)
Distance (F3) is geometric; surprise (F4) is epistemic — *did it violate a held assumption?* A `5`
overturns something the team believed; a `1` merely confirms. Keeping them distinct lets S1-1 say
*"valuable surprise = serendipity-band distance AND surprise ≥ 3"* — catching the case where two
domains are geometrically mid-distance but the connection was already obvious (low felt surprise).

**Rating source (PO-approved, Q3):** `surprise` is **agent-rated at capture**; triage may adjust;
**log both** (`:surpriseAtCapture`, `:surpriseAtTriage`). Modelled naturally in PROV-O: the
triage-adjusted discovery is a `prov:wasRevisionOf` the captured one, so both values and who set them
are provenance-traceable. Each `surprise ≥ 4` claim carries an epistemic marker from `SKILL.md`
§Step 3 (`[known] [hypothesis] [verify] [check:<term>]`) so felt surprise is auditable, not asserted.

## 3. Domain vocabulary as a SKOS concept scheme (anchors both distances)

Density and distance both need discoveries **anchored to domains**. The ontology does not hardcode a
domain list (that's domain content — it belongs in a content pack, per `SKILL.md`). It models the
anchor layer as **SKOS**:

- **`:DomainScheme` is a `skos:ConceptScheme`.** Each domain is a `skos:Concept` with a
  `skos:prefLabel`. `skos:broader`/`skos:narrower` express granularity; `skos:related` links
  neighbouring domains.
- **Source of truth = the loaded content pack.** A discovery's `domains[]` are `skos:Concept`s drawn
  from the pack's agent-library domains. The generic example pack's agents (Physics Bridge, Materials,
  Demand Scanner, Org Systems & AI, …) are the domain concepts when no custom pack is loaded.
- **Granularity (PO-approved, Q2): agent-level.** Each pack agent = one `skos:Concept` (the generic
  pack yields ~14 domain concepts). Finer granularity is available later via `skos:narrower` if
  density proves too noisy, without changing the scheme.
- **Primary vs secondary:** `:primaryDomain` = the domain the discovery most *lives in* (usually the
  transfer target); `:secondaryDomain` = the other domain(s) it touches. A Type-B Bridge has ≥2
  domains; a Type-A Anomaly may have 1.

```turtle
:DomainScheme a skos:ConceptScheme ; skos:prefLabel "Discovery domain scheme (pack-loaded)" .
:physics-bridge a skos:Concept ; skos:inScheme :DomainScheme ; skos:prefLabel "Physics Bridge" .
:org-systems   a skos:Concept ; skos:inScheme :DomainScheme ; skos:prefLabel "Org Systems & AI" .
```

## 4. Typed relationships (OWL object properties between discoveries)

Four edge types, each an `owl:ObjectProperty` with declared characteristics. Edges are stored on the
board via `relatedIds[]` today; the **named minimal addition** `relations[] = [{ toId, kind }]` is a
typed upgrade.

| Edge | Meaning | OWL characteristics | Board mapping |
|------|---------|---------------------|---------------|
| **converges-with** | Points at the *same underlying insight* from a **different** domain. ≥3 mutual = a Convergence. | `owl:SymmetricProperty`, `owl:IrreflexiveProperty` | `convergence` bool + `relations[]` |
| **bridges** | Connects two otherwise-distant domains via a shared mechanism (the Type-B act as an edge). | directed; `owl:IrreflexiveProperty` | `relations[]` |
| **refines** | Narrows / sharpens a prior discovery at higher resolution, **same primary domain**. | directed, acyclic (newer→older) | `relations[]` |
| **supersedes** | Replaces / subsumes / invalidates a prior discovery. | directed, acyclic (newer→older) | `relations[]` |

### 4.1 Convergence as a first-class node (upgrade of today's boolean)
Today convergence is a per-discovery boolean set when "3+ agents point at the same insight"
(`SKILL.md` §Step 4). The ontology promotes it: a **`:Convergence`** is a derived node binding ≥3
discoveries mutually `converges-with`-linked, spanning **≥3 distinct primary domains** — deliberately
cross-domain (same-domain agreement is redundancy, not convergence). S1-2's geometry populates this
automatically instead of a manual checkbox. (Enforcement needs SPARQL-based SHACL — §7.3.)

## 5. Provenance in PROV-O (F7)

Provenance is a **strong** standards fit, so F7 is modelled directly in PROV-O rather than as ad-hoc
fields:

- **`:Discovery` ⊑ `prov:Entity`.**
- The capture event is a **`prov:Activity`** (`:CaptureActivity`); the discovery
  `prov:wasGeneratedBy` it, with `prov:generatedAtTime` = `discoveredDate`.
- **`sourceAgent`** = a `prov:SoftwareAgent` (the discovery agent lens); **`discoveredBy`** = a
  `prov:Agent`; the discovery `prov:wasAttributedTo` both.
- **`captureMode`** (PO-approved enum `{deliberate-scan, ambient-emitter, manual}`) is a property /
  subclass of the `:CaptureActivity` — this is what lets density weight ambient captures (§6) and
  ties to the S1-4 emitter spike.
- **Triage adjustment** (Q3): the triaged discovery `prov:wasRevisionOf` the captured one, so
  `surpriseAtCapture` vs `surpriseAtTriage` (and who changed it) are recoverable.

```turtle
:DISC-001 a :Discovery, prov:Entity ;
  prov:wasGeneratedBy :cap-DISC-001 ;
  prov:wasAttributedTo :agent-physics-bridge .
:cap-DISC-001 a :CaptureActivity ;
  :captureMode "deliberate-scan" ;
  prov:startedAtTime "2026-05-07"^^xsd:date .
```

Provenance (`generatedAtTime` + `captureMode`) is exactly the half of the density calculation SKOS
can't supply — which is why F2 (SKOS anchor) + F7 (PROV-O) *together* make density measurable.

## 6. Domain-density — the required measurable (design requirement)

**The requirement:** detect when *enough discoveries cluster in one domain*. F2 (SKOS Domain Anchor) +
F7 (PROV-O `generatedAtTime`, `captureMode`) supply exactly what's needed. Density is defined
formally so S1-3 inherits a computable metric (purpose-built — no standard for this). **Per the S1-1
reframe, density is a `ValueScore`-weighted SUM, not a FLOOR-gated count** — no-exclusion applied to
the density signal: low-value discoveries contribute *fractionally*, never zero:

```
density(d, W) = Σ  ValueScore(x)     over discoveries x with:
                      d ∈ x.domains                    # SKOS concept membership (F2)
                      ∧ x.generatedAtTime ∈ W          # PROV-O window (F7)
                                                        # NO hard floor — value-weighted, not gated
```

- `d` = a `skos:Concept` from the domain scheme (§3); `W` = a rolling window; `ValueScore(x)` ∈ [0,1]
  is S1-1's graded value (`spec-value-weighting.md`). All inputs come from facets this ontology defines.
- **Soft floor (was a hard FLOOR):** a discovery with `ValueScore < 0.35` (S1-1) is *Bank-eligible* and
  down-weighted, but **still counts** — its small `ValueScore` is exactly its small contribution here.
  Nothing is excluded from the density signal.
- **Venture / partnership candidate (detection only).** When `density(d, W) ≥ DENSITY_THRESHOLD`
  (set in S1-3), domain `d` is flagged a **venture/partnership candidate** and escalated to the PO.
  *The ontology defines the measurable and the flag; the go/no-go stays with the PO.* Engine detects
  and escalates; PO decides. (Hard line, per charter + sprint risk log.)
- **Why density needs the ontology:** you cannot value-weight "discoveries clustering in a domain"
  until discoveries are (a) anchored to SKOS domains and (b) scored on shared facets. That's why S1-0
  is upstream of the venture-candidate output.
- **Anti-inflation guard:** because contribution = `ValueScore`, a flood of low-value ambient captures
  adds little; `captureMode = ambient-emitter` items are further weighted down until they pass triage,
  so cheap volume can't fake a cluster. (Ties to the S1-4 emitter spike and the "capture inflation" risk.)

## 7. Validators as SHACL shapes (well-formedness)

Validators are the enforcement layer, expressed as **SHACL shapes** so they are *tool-checkable*
against the RDF graph rather than hand-run prose. A characterization is **well-formed** iff all
shapes report conforming. Grouped node shapes and edge/property shapes; each carries a severity
(`sh:Violation` = hard reject, `sh:Warning` = soft).

### 7.1 Node shape — `DiscoveryShape` (core SHACL)
Covers the former V-N rules:

```turtle
:DiscoveryShape a sh:NodeShape ; sh:targetClass :Discovery ;
  sh:property [ sh:path :discoveryType ; sh:minCount 1 ; sh:maxCount 1 ;
                sh:in ( "A" "B" "C" "D" ) ; sh:severity sh:Violation ] ;
  sh:property [ sh:path :primaryDomain ; sh:minCount 1 ; sh:maxCount 1 ;
                sh:class skos:Concept ; sh:severity sh:Violation ] ;
  sh:property [ sh:path :surprise ; sh:minInclusive 1 ; sh:maxInclusive 5 ;
                sh:datatype xsd:integer ; sh:severity sh:Violation ] ;
  sh:property [ sh:path :impact ; sh:minInclusive 1 ; sh:maxInclusive 10 ; sh:severity sh:Violation ] ;
  sh:property [ sh:path :serendipityPotential ; sh:minInclusive 1 ; sh:maxInclusive 10 ; sh:severity sh:Violation ] ;
  sh:property [ sh:path :generality ; sh:in ( "point" "vertical" "platform" "universal" ) ; sh:severity sh:Violation ] ;
  sh:property [ sh:path :distanceBand ; sh:in ( "too-close" "serendipity-band" "too-far" ) ; sh:severity sh:Violation ] ;
  sh:property [ sh:path :captureMode ; sh:in ( "deliberate-scan" "ambient-emitter" "manual" ) ; sh:severity sh:Violation ] ;
  sh:property [ sh:path prov:generatedAtTime ; sh:minCount 1 ; sh:severity sh:Violation ] .
```
Plus: Type **B** ⇒ ≥2 domains (qualified cardinality on `:primaryDomain`+`:secondaryDomain`);
`surprise ≥ 4` ⇒ epistemic marker present (`sh:Warning`); lifecycle transitions restricted to the
board's allowed `next[]` edges (a `sh:sparql` check against prior state — §7.3).

### 7.2 The bridge-claim integrity shape — `BridgeShape` (core SHACL)
**Scope (rev 3): this validates a `bridges` *claim*, not a discovery's worth.** An edge *typed*
`bridges` is well-formed only when its endpoints sit in the serendipity band; outside it, the edge is a
mis-typed assertion ("this isn't a bridge"). Severity stays `sh:Violation` — but the **remedy is to
*retype* the edge/discovery, never to exclude the discovery**, which stays and is weighted normally
(often it was an Anomaly, not a Bridge):

```turtle
:BridgeShape a sh:NodeShape ;
  sh:targetSubjectsOf :bridges ;
  sh:property [ sh:path :distanceBand ; sh:hasValue "serendipity-band" ;
                sh:severity sh:Violation ;
                sh:message "a `bridges` CLAIM requires the mid-distance band; outside it, RETYPE the claim — do not exclude the discovery" ] .
```

Note the division of labour: this hard check answers *"is this a well-formed bridge claim?"* (integrity).
Whether a too-close/too-far discovery is *valuable* is a separate, **soft** question answered by the
peaked `g_dist` weight in S1-1 (which down-weights but never drops). One band definition (`τ_lo,τ_hi`
from S1-2), two consumers — hard claim-check here, soft value-weight in S1-1.

### 7.3 Constraints that exceed core SHACL → SPARQL-based SHACL (flagged)
Two rules are **not expressible in core SHACL** and require `sh:SPARQLConstraint` (still SHACL, but
the SPARQL extension). Naming this explicitly is part of the deliverable (§8):

- **Acyclicity of `refines` / `supersedes`** (they must form a DAG). Core SHACL has no transitive
  closure; a `sh:sparql` constraint detects a path back to self.
- **`:Convergence` requires ≥3 discoveries across ≥3 distinct primary domains.** Needs
  `COUNT(DISTINCT ?domain) >= 3` — a `sh:sparql` constraint, since core SHACL cardinality can't count
  *distinct values of a joined property*.
- Also SPARQL-based: `converges-with` must join **different** primary domains (V-E2), and lifecycle
  transition legality (compare to prior `:lifecycleState`).

Soft (`sh:Warning`) shapes: a superseded discovery left `Active` (should trend to `Banked`);
`surprise ≥ 4` without an epistemic marker.

## 8. Where standards *don't* fit (reasoning captured — Orin's ask)

Adopting standards is only credible if the misfits are named. Four:

1. **The serendipity band (F3) has no standard.** SKOS gives domain *identity and hierarchy* but no
   continuous metric; RDF/OWL give no notion of "mid-distance." The band is intrinsically about
   *embedding geometry* + a *value judgment* ("near enough / far enough"), which is the novel science
   here. → **Purpose-built**, anchored to SKOS concepts, thresholds set empirically in S1-2.
2. **Surprise Magnitude & Serendipity Potential (F4, F9) have no standard.** These are epistemic
   measures (assumption-violation; expected-payoff-of-surprise). No W3C vocabulary models them. →
   **Purpose-built** datatype properties with defined ordinal scales; PROV-O carries *who rated and
   when*, which is the part a standard *can* do.
3. **Core SHACL can't express acyclicity or distinct-cross-domain counting** (§7.3). → Adopt SHACL,
   but use its **SPARQL extension** for those two shapes. Honest boundary of the tool, not a reason to
   abandon it.
4. **A/B/C/D discovery types (F1) are novel content.** The *vocabulary shell* could be published as a
   SKOS scheme for interoperability, but the four types are this project's own epistemology
   (Anomaly / Bridge / Constraint-flip / Scale-shift). → **Purpose-built**; SKOS-publishable later if
   external interop is ever wanted.

General principle borne out: **standards fit the identity, provenance, structure, and validation
layers; the novel *measures of surprise and value* are ours to define.** That division is exactly
where the project's real science lives.

## 9. Board-field mapping & the JSON-LD bridge (for S1-3)

The RDF/OWL model is the **canonical spec**; the board stores plain JSON. **JSON-LD** bridges them
with zero rewrite: a single `@context` maps existing board keys to RDF terms, so today's board data is
*already* valid RDF once the context is attached.

```json
"@context": {
  "type": "@id",                     "discoveryType": "@id",
  "priorityScore": ":priority",      "status": ":lifecycleState",
  "discoveredDate": "prov:generatedAtTime",
  "sourceAgent": "prov:wasAttributedTo", "domains": ":primaryDomain"
}
```

**Already computable from stored fields:** F1 (`type`), F5/F9 (`priorityScore` factors), F8
(`status`), provenance basics (`sourceAgent`,`discoveredBy`,`discoveredDate`), untyped links
(`relatedIds[]`), `convergence` bool, `tags[]`.

**Named minimal additions (the whole delta):** `domains[]` (primary flagged), `surprise`,
`generality`, `captureMode`, `distanceBand`/`domainDistance`, and typed `relations[]`. Six additions,
all additive/nullable — no board rewrite, no migration. This is the "one named minimal addition" the
sprint DoD asks S1-3 to compute against.

## 10. What each downstream item inherits

- **S1-1 (PO characterizes valuable surprise):** expresses the value region as predicates over
  F1/F3/F4/F5/F6 — e.g. *"type ∈ {B,C} ∧ distanceBand = serendipity-band ∧ surprise ≥ 3 ∧ impact ≥ 6"*
  — plus the "hit" lifecycle event (F8) and the priority `FLOOR`. (Can be authored as its own SHACL
  shape: "valuable surprise" becomes a conformance target.)
- **S1-2 (distance band):** sets the numeric thresholds for F3's three bands; `BridgeShape` enforces
  them.
- **S1-3 (funnel + density):** funnel = transitions over F8; density = §6 formula (SKOS anchor +
  PROV-O time + `FLOOR`); venture-candidate flag = §6 threshold. Detection only.
